# Backup format and safety

Format identifier: `practice.logger.backup`. Writer format version: integer `4`; reader accepts legacy `1`/`2`/`3` and current `4`. UTF-8 JSON. Independent of Room schema version (currently 7). The app uses Android's CreateDocument/OpenDocument picker; it requests no broad storage permission. Android owns the picker typography.

Top-level fields: `format`, `version`, `blocks`, `sessions`, `placements`, `routines`, `routinePlacements`. Format 4 requires the two routine arrays; formats 1–3 import with empty routines/entries. All record fields for the declared format are required, including explicit JSON null for nullable values. Format 3 adds nullable placement lastUsedBpm; formats 1/2 omit it and import as null. Unknown extra fields are ignored; unknown format versions are rejected. IDs are preserved.

- Blocks: id, name, action, durationMinutes, tempo (nullable), notes, archived, createdAt, updatedAt.
- Routines: id, name (trimmed, 1–120 characters), createdAt, updatedAt.
- Routine placements: id, routineId, sourceBlockId, position, configuredMs. Stable Block/routine references, positive durations, nonempty routines and contiguous zero-based order are required. Archived Block references are retained and visibly prevent starting until repaired/restored.
- Sessions: id, startedAt, endedAt (nullable), status, currentIndex, note.
- Placements: id, sessionId, sourceBlockId, name, action, tempo (nullable), referenceNotes, position, configuredMs, activeMs, outcome, overtimeAccepted, note, lastUsedBpm (nullable, 30–300 when present).

Export reads a consistent Room transaction. It includes all saved routines/placements, archived Blocks, completed history snapshots, notes and at most one builder draft and every unfinished active session. No monotonic clock anchor/running flag is exported; restored active sessions resume paused. Quick notes must be saved with Save Block note, Save for later, Back, Complete or Skip before export; typing alone is not a durable save. Session notes require Save note before export.

Limits: 8 MiB UTF-8 file, 20,000 records per type, nesting at most 32 levels. Validation rejects missing/wrong field types, out-of-range integers, duplicate/blank IDs, broken links, nonpositive duration/tempo, negative elapsed time, noncontiguous placement order, unsupported statuses/outcomes, inconsistent current position/outcomes, multiple builder drafts and overflowing active-time totals. Malformed UTF-8 and trailing content are rejected. This is structural validation, not encryption or cryptographic authentication: keep backups private and restore only trusted files.

Restore first parses/validates the complete file and shows counts for confirmation. The repository validates again, checks that Blocks, sessions, routines and take metadata are all empty, then inserts everything in one database transaction. Any error rolls back all inserts. Restore never clears, replaces or merges data. It supports a fresh app/new phone; it intentionally offers no reset button. **Do not clear/uninstall the current app just to test restore.** Use a spare device or disposable test installation.

Cancelling the picker or confirmation does not change the database. Rotation retains an in-memory restore preview and operation state. Process death loses an unconfirmed preview; select the file again. A failed export may leave a partial document, which must not be treated as a completed backup; choose a new export and wait for the success message. Export does not modify database contents. Android CreateDocument preserves an existing same-name document by choosing a distinct name. Provider-specific availability, cancellation, disk-full behavior and large-text accessibility still require owner phone testing.

Tests cover a real JSON file round trip into an empty database and reopening, archived Blocks/Unicode/notes/historical snapshots/drafts/overrides, unfinished overtime recovery, malformed/version/type/size/depth/trailing/relationship/order/state rejection, protected nonempty target, and rollback after an injected mid-restore write failure. Device tests additionally exercise the backup screen, recreation and retained confirmation, real file export and restored database reopen, confirmation cancellation, rejected overwrite and malformed file. The original device harness supplies local file URIs directly to the same ViewModel operations. Additional API 26/35 UI Automator tests now open the real Android system picker, export into Downloads, cancel export/import, restore into a cleared disposable test app, compare all records and force-stop/reopen restored paused practice and history. Unavailable-provider export/import and successful retry are verified separately. No owner app is cleared by these CI tests.

Stage 3 engineering checks are complete on the supported minimum API 26 and API 35; 200% text workflows and screenshots are verified. Dependable daily-use acceptance still requires owner phone document-provider export, spare-device restore, interrupted export and TalkBack/accessibility confirmation. Merge/replace restore, cloud sync and in-app update controls are outside this increment.

Format 2 extends the allowed session set to multiple IN_PROGRESS sessions plus at most one DRAFT. All per-session validation is retained. Legacy format 1 still requires at most one unfinished session; older app versions reject format 2 safely. The 0.3.3 increment kept Room schema 2; Stage 5 now explicitly migrates it to 3. Multi-session backup/restore/reopen is covered by a targeted unit test.

Stage 5: Room 2→3 adds nullable lastUsedBpm without rewriting existing records. JSON format 3 exports this history value separately from the original tempo snapshot/default. Formats 1 and 2 restore with null lastUsedBpm; older app builds reject format 3 safely. Audio playback state is never backed up or resumed. No recording/audio files exist in Stage 5; JSON remains database-only.

## Stage 6A recording limitation

Room 3→4 creates a separate takes table (stable ID, Block ID, creation time, FREE mode, duration, private file name, optional label) with Block reference and unique file-name indexes. Existing practice tables and JSON format 3 remain unchanged; all old migrations/readers remain available.

JSON export excludes both take metadata/labels and audio. Restoring JSON restores practice data with no takes, so it never creates playable-looking references to missing media. Archive/restoration of an existing Block retains its takes on the same device. Audio is held privately under files/recordings; platform backup/device transfer remain explicitly excluded.

Use Export audio for each take to create a normal AAC/M4A file through Android's document picker. Export failure preserves the source but may leave a partial destination; retry to a new file. Exported audio has no automatic app import or bulk restoration path. Clearing/uninstalling the app or losing the phone loses unexported recordings and labels. Full audio-inclusive backup/restore is not implemented or claimed; later bulk portability must be designed and verified separately.

Storage writes use generated UUID pending files, validated playable duration, file sync and rename before metadata commit. Startup removes interrupted/unreferenced generated files after successfully reading all metadata, while retaining saved takes and any current in-process capture. A killed unsaved capture may be discarded; previous saved takes remain. Missing/corrupt saved files report an error when accessed rather than fabricating playback. Delete removes one metadata row and its file; interrupted file cleanup is retried at startup.
## Stage 6B phrase loops
Room4→5 adds nullable recordedBpm and beatCount to takes; old FREE rows/files/labels remain untouched and get null phrase fields. LOOP rows reference canonical PCM16 mono48kHz WAV files and retain fixed BPM/beats; exact whole-phrase frame length is round(60×48000×beats/BPM). Per-take export writes one normal WAV phrase byte-for-byte, while FREE export remains M4A. Private UUID pending WAV files use the same validated/synced/rename-before-metadata protocol; incomplete or cancelled phrases are not playable saved takes. Recovery handles both generated WAV and M4A names. JSON writer/reader remains format3/legacy1–2, excluding all take rows/labels/audio. Broader save/storage/bulk restore is deferred by owner until after phrase looping; no audio import/media restoration claim.

## Saved Routines / format 4 (2026-10-28)

Room7 adds routines and routine_placements without rewriting existing tables. JSON4 preserves their stable IDs/order/durations. Restore inserts Block/session/placement/routine/entry records in one transaction; an insertion failure rolls back all data. A target with any Blocks, sessions, routines or recording metadata is nonempty and cannot be overwritten. Legacy1–3 files remain readable with no invented routines. Future versions are rejected. Room migrations do not change audio files. All Block/standalone free takes and loops, labels and audio remain excluded from JSON; export wanted takes separately. Existing historical format notes below/above describe their original releases.

## Goals / format 5 (2026-10-28)
Writer5, readers1–5, Room8. Required arrays goals (id,title,description,progress,notes,completed,priority,createdAt,updatedAt), goalBlocks(goalId,blockId,position), sessionGoals(sessionId,goalId). Goal IDs unique/nonblank; title nonblank, manual progress0–100, nonnegative ordered timestamps. At most5active Goals with contiguous zero-based priority; completed priority=-1. Unique Goal/Block pairs, existing references and contiguous Block-link positions; one Goal per non-draft existing session. Per-Goal time overflow rejected. Legacy1–4 imports with no invented Goals/attribution; shared Block history is never retroactively attributed. Restore checks Goals as well as all prior tables for emptiness and inserts atomically. Format5 excludes ALL takes/labels/audio as before.
