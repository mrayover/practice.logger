# Compact Composer UI and Save As

Owner-assigned consolidation after C3, before C4. [Delivery/evidence](../CURRENT_STATE.md) · [C3 audio](COMPOSER_C3.md) · [Project format](COMPOSER_C1.md).

Four compact rows group application/document actions; instrument/pattern context; transport/mixer; and piano-roll editing. Undo belongs with editing; Create Pattern is in Pattern (missing A/B/C only); the compact ↤ transport menu retains Beginning. Instrument shows its track number, with number/title in its selector. Sound retains all nine banks. Disabled Edit Instrument and Velocity reserve future positions. Arrange uses the same shell with an explicit placeholder and disabled Play.

Each row measures actual Lato labels at current font scale, includes bounded slider widths, and moves lower-priority controls into an explicit More menu before total width exceeds available width. Primary controls remain visible where space allows. Menus scroll vertically when necessary; no surrounding toolbar scrolls horizontally. Narrow/enlarged configurations require More for some controls. The musical canvas still pans/zooms. Forty-dp compact controls and one status line return remaining height to the unchanged keys/grid/ruler. Actual evidence and physical limitations belong in CURRENT_STATE.

PianoRollWorkspace remains the sole audio/editor-state owner. Opening menus, sliders and width changes do not recreate ComposerAudio. Loop/Arrange changes stop transport deliberately, preserving session choices and clipboard. A new project identity after Save As deliberately disposes the old workspace/audio owner and starts fresh view/selection/clipboard state.

Save As prefills a bounded title plus Copy and applies existing validation. It copies current in-memory musical edits. Project/track/pattern/note/clip UUIDs are fresh and clip references are remapped. Tempo, meter, sound assignments, musical values and arrangement placement remain. Creation/modification metadata starts fresh; revision starts at zero. CompositionStore.create validates, syncs and commits atomically. Only after creation does the ViewModel switch its committed/current project and saved-state/Intent identity, clear source Undo, and retire the old draft checkpoint under the draft lock. Original committed bytes are never saved/renamed by this action. Validation/storage failure leaves the source draft recoverable. Save As creates a device-local editable composition, not an export. Practice backups still exclude Composer until C7.

Focused host checks cover remapping, original preservation, unsaved edits, independent saves, revision reset, recovery, title rejection and simulated precommit failure. The scoped native workflow checks real rendering, menus, Save As/keyboard, playback/mixer, Actions/Undo, navigation guards, library presence and exact documents after force-stop. See CURRENT_STATE for actual outcomes; no physical-phone/F1 acceptance is implied.
