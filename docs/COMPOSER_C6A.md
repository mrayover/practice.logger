# C6A — Offline WAV and M4A backing tracks

Export Audio in the responsive Composer application row (or More overflow) offers Current Loop or Full Arrangement and M4A / AAC (default) or WAV. Choose destination uses Android Create Document with the composition title and sanitized extension. No storage permission, fixed output folder, Library import or save prerequisite is added.

Current Loop freezes the same per-track pattern choices used by Loop/Mixer, including transient clip-to-pattern navigation. Shorter patterns repeat inside exactly one longest global region. Arrange freezes validated songSnapshot absolute clip events for one traversal ending at the latest clip end. Existing 200,000 expanded song-note budget applies. Off events precede ons at equal sample frames. Endpoint ons are suppressed; residual held notes are released normally. Empty time stays silent. Documents, revision and Undo are unchanged.

The separate bounded native context loads only referenced existing SoundFont banks. It uses the same custom sound envelopes/filter/pan, velocities, track gain, mute/solo, four-band EQ, width and mixer pan. Master Volume scales already clipped PCM16 once, equivalent to live AudioTrack volume after the native output conversion. No AudioTrack, microphone, focus request, realtime recording, wall-clock music timer or extra playback worker is created. Existing live output is stopped before rendering and controls restore afterward.

PCM chunks contain at most256 stereo frames. WAV writes signed16-bit little-endian stereo48kHz directly, then finalizes RIFF lengths and syncs. M4A feeds those chunks directly to Android MediaCodec AAC-LC at48kHz/stereo/192kbps, drains encoded output while supplying input and muxes a genuine MPEG4 container. Encoder configuration/drain/finalization failure is explicit; there is no silent format substitution or uncompressed AAC intermediate. Encoder stalls have a10-second inactivity guard. See Android [MediaCodec](https://developer.android.com/reference/android/media/MediaCodec) and [MediaMuxer](https://developer.android.com/reference/android/media/MediaMuxer).

The tail upper bound reads installed factory SF2 amplitude-release seconds and enabled custom release values. It stops when active voices finish or the smaller of that bound and the documented30-second safety ceiling, plus100ms, is reached. One-shot percussion may declare a long release but finishes at the end of its sample; that declaration does not refuse export. Custom controls allow up to5seconds. At most one256-frame final chunk of silence is included. No arbitrary long silence or repeated endpoint is appended.

The shared duration guard reserves31seconds below the RIFF unsigned32-bit size ceiling: `(2^32-1-36)/4` stereo frames, about6hours12minutes total at48kHz. This also bounds AAC work for pathological distant clips. All scheduling/storage arithmetic uses Long; rendering memory is independent of audio duration. WAV staging reserves maximum frames×4+44; M4A reserves twice the target bitrate plus16MiB container allowance. Both retain8MiB free-space margin and check available storage every second of rendered PCM. Actual disk/provider/codec failures are still caught. Long exports can exceed the Library's separate50MiB/15-minute import limits; external export does not imply Library eligibility.

One private finalized file is copied in64KiB chunks to the selected provider. Success appears only after finalization and destination stream close. Cancel, app stop, encoder/native/write failure and ViewModel disposal release resources and remove staging plus the newly created destination when supported. A provider that refuses cleanup is reported explicitly. Process-loss recovery clears only export-owned temporary files and the remembered interrupted destination on the next Composer export owner creation. No composition, preset, practice recording or Library original is part of export cleanup. Process termination can leave an external partial document if the provider grant or saved lifecycle state cannot be recovered; no successful-export indication survives it.

Ordinary development verification is scoped to the new renderer, encoders, file safety, mixer representatives and Android export/return workflow. Actual results and signed provenance are in [CURRENT_STATE](../CURRENT_STATE.md). Physical-phone acoustics and nonlocal provider behavior require owner checks.
