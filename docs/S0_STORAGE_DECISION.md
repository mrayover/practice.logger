# S0 — Storage and recovery decision

November 4, 2026 · Reviewed against `86f93125f0bb507ae16cb71c3f697382c2745ebd` and signed 0.27.0/build91. The [V1 master plan](../PRACTICE_LOGGER_V1_MASTER_PLAN.md) governs scope.

## Decision

Use Android's Storage Access Framework (SAF) for both features. A persisted writable tree is an optional convenience for organized copies. The system's single-file Save As picker is the baseline for both audio export and portable ZIP backup. A provider can expose a writable Save As destination without offering a selectable tree or supporting programmatic directory creation. Drive, OneDrive and other providers are usable only for operations they expose on the device and account in use. App-private recordings and data remain authoritative.

## Evidence and provider coverage

- **Previously exercised on Android:** the [passing API 26 diagnostic](https://github.com/mrayover/practice.logger/actions/runs/40899553803/job/123537782782) ran the existing recording workflow. It selected Downloads through the system Save As picker, wrote an M4A copy and compared its length to the original. A separate attempt using a nonexistent provider URI reported failure and left the original present. The check establishes a local single-file write and missing-authority handling in that historical build. It measured length and did not check cloud upload or simulate revocation.
- **Existing code reviewed in S0:** `RecordingSheet` launches `CreateDocument` with the recording MIME type, `RecordingViewModel` opens the output, and `RecordingRepository.export` copies bytes from `files/recordings`. `BackupScreen` uses the system picker for JSON. The existing `BackupWorkflowTest` injects a local file URI for JSON export/preview and tests restore protections. That test is evidence of the app's JSON path, independent of provider interoperability. The current JSON 7 codec omits media and standalone Transcribe activity. [Existing backup contract](../BACKUP_FORMAT.md)
- **S0 runtime availability:** ADB listed no devices. No fresh Android/provider trial was run. A stock emulator can cover the local path but cannot settle the behavior of signed-in Drive or OneDrive on the owner's phone.

## S1 — Organized audio export

1. Add Settings → Storage to choose, inspect, replace or forget an export root. Use a tree picker result that exposes grant flags. Persist only the returned read/write modes and accept a reusable root only when both modes are available and the root can be queried. Store the URI and a display label. Check persisted modes and current access before export, release the superseded grant after successful replacement, and release it on Forget. Keep the existing destination if a replacement is cancelled. Prompt for reselection when access is lost and offer retry when a provider is temporarily unavailable.
2. Treat the chosen folder as the app root. Resolve or create `Recordings/<Block>/<YYYY-MM-DD>/` or `Recordings/Free Recordings/<YYYY-MM-DD>/` one segment at a time with tree-scoped URIs. Use the take's saved creation time in the local timezone. Sanitize and bound display names, append the stable Block ID to distinguish same-name Blocks, and reserve the standalone folder name. Resolve existing folders by their unique Block ID suffix within the chosen root so a Block rename can reuse its export folder. Ambiguous or unusable folders require a new selection or Save As. Leave prior copies where they are.
3. Use the roadmap's time/label or time/beats/BPM names, a short take-ID suffix and the original extension/MIME type. Preserve imported MP3/M4A/WAV bytes. If the candidate name is occupied, choose a fresh suffix. Serialize this app's writes and use create-only operations and returned URIs even if another client adds a same-name file concurrently. Report the actual destination name when available. Never open an existing copy for replacement.
4. Reuse the current per-take streaming copy on IO. Check the selected saved take before creating a destination. Count streamed bytes, check the expected source length and treat open, copy and close errors as failures. Record the new output URI while a write is pending so interruption can be reported after restart. On failure or cancellation, best-effort delete only the output created for this attempt if the provider permits safe cleanup. If cleanup fails or completion is uncertain, identify the possibly incomplete copy and retry to a new file. Private originals stay in place.
5. If the tree is missing, read-only, unavailable, cannot create the hierarchy or rejects the write, offer **Save As** using the existing per-take `CreateDocument` flow with the suggested name. The user can pick a writable location or another provider. If the provider is absent from Save As too, the user can choose local storage or another listed provider. Cancelling leaves the take available for another attempt.

## S2 — Complete ZIP backup and restore

1. Use a versioned logical ZIP independent of Room's on-disk format. Take a consistent Room snapshot and coordinate with the recording, legacy visual and Media Library file mutation/recovery paths while reading the referenced immutable originals. Checkpoint saved practice state and capture durable portable preferences such as audio/count-in and theme. Include all durable records and stable relationships specified by the roadmap, including standalone Transcribe time and optional associations, master/local audio annotations and playback state, legacy visual references and imported takes. Archive each canonical original once. Exclude pending recordings, unsaved drafts, caches, device grants and secrets.
2. Stream to an app-private temporary ZIP with a manifest listing format/schema/app versions, item IDs, paths, counts, types, sizes and SHA-256. Bound resource usage, preflight storage, and verify the completed archive against the manifest before opening the external destination. A missing source or failed integrity check aborts creation. Reuse the verified staged ZIP for a retry during the same operation and clean up staging on cancellation or recovery.
3. Use `CreateDocument("application/zip")` with a timestamped filename as the baseline destination flow. Offer `Backups/` under a writable selected tree when supported. For tree providers proven to support rename and cleanup, stream to a uniquely named pending document, close it, read back and compare size/hash, then rename to a fresh final name using the returned URI. For Save As, stream the already verified ZIP to the new URI, close it and compare size/hash where read-back works. Report a read-back failure or unavailable verification explicitly and offer another destination. If a copy fails, attempt safe cleanup of that new document and identify any partial copy that remains. Treat provider write completion, read-back verification and cloud sync as separate outcomes.
4. Restore from the system file picker into a private staging area. Before applying anything, validate format, entry count and expanded-size limits, duplicate/traversal paths, checksums, IDs, file types, references, and free space. Show a preview and require confirmation. Reject a populated installation and recheck emptiness in the same Room transaction that inserts rows, including targets containing only takes, media, Logs or Transcribe activity. Keep restored sessions paused. Retain legacy data-only JSON readers 1–7 and their empty-installation guard.
5. Serialize restore against other writes and orphan recovery. Stage and sync validated media on the same filesystem, then promote the files before committing their database references. Use a durable restore journal recording owned paths, prior/desired portable preferences and a commit witness written with the restored rows. Gate startup and recovery until the journal can remove uncommitted promoted files or finish applying committed preferences. Clear the journal only after finalization. This preserves the empty target on pre-commit failure and recovers a committed restore without exposing dangling media or an incomplete application state. Verify forced interruption around promotion, commit and preference finalization as part of S2, along with the full roadmap round trip on a spare empty installation.

## Remaining phone checks

- Record Android version and each provider app/account type. In local storage, Drive and OneDrive separately, check whether the picker shows the provider for both folder choice and Save As. Check another compatible provider if available.
- With a disposable folder and sample recording, test selection, restart/reboot persistence, nested folder and file creation, repeated names, byte read-back and actual provider display names. Confirm originals still play. If the tree path fails, exercise Save As and record which operation failed.
- On disposable destinations, revoke the grant or move the selected folder, go offline and interrupt an in-progress copy. Check reselection/retry, incomplete-copy reporting and cleanup, and cloud visibility after reconnect. Capture provider and operation-specific results. Perform the ZIP round trip and recovery checks in S2 without clearing the owner's installed app.
