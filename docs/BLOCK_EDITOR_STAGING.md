# Block editor staging (Stage 2)

The editor keeps one visual (image OR PDF) and one audio selection. It does not create a placeholder Block. Existing Library originals are selected by stable ID; replacements and removals take effect only on Save Block. The form retains the existing notes/source column, primary Goal, Block identity and history model. Room23, JSON7 and complete ZIP7 are unchanged.

`BlockEditorMedia` uses `MediaLibraryRepository.stage`, the same bounded copy, MIME/content validation, decoder and hash validation as normal Library imports. Staging writes only under `files/block-editor-staging/<editor UUID>`. The camera and gallery use the existing capture provider and contracts. The private manifest is synced before atomic rename and records selections, staged metadata, original attachment identities, and a reserved creation UUID. That UUID is not inserted into the database until Save.

Rotation retains the ViewModel and saved form state. Activity/process recreation with Android's saved navigation state reopens the manifest by editor UUID. Incomplete copies outside its manifest are removed on reopen. A completed creation row witnesses a commit interrupted before navigation; a small completion receipt also handles ordinary post-save recreation. Repeated Save returns the same created Block without appending another builder placement. Force-stop without Android state restoration abandons the editor rather than creating a Block. On the next editor open, other staging directories older than seven days are removed. Completed receipts and abandoned private camera files expire through the same seven-day mechanism. A restored completed-save receipt returns to the origin automatically. Uncommitted drafts are temporary and intentionally excluded from portable backups.

Save validates the draft and changed selections, takes the existing legacy-reference then Library file locks, matching portable backup/restore, copies selected temporary originals into canonical storage, syncs them, and commits new media rows, Block fields, Goal, selected-week membership, reference links and any builder append in one Room transaction. Existing source identities are rechecked. Unchanged links, playback settings, annotations and historical placement snapshots are untouched. The editor explicitly confirms before offering replacement/removal of an existing reference; final transaction checks still reject stale visual/audio identities or unreviewed visual markings.

The temporary original remains available until commit succeeds. An exception rolls back all database writes and deletes only promoted files whose absence from the database can be established. If that read fails, canonical bytes remain for existing Library recovery, which runs under the same file mutex and removes only proven orphans. A process interruption before commit similarly leaves recoverable staging and canonical orphans for the established cleanup. After commit, temporary originals are removed, the receipt is retained, and legacy orphan cleanup runs. No shared original is deleted by Cancel or unlink. Confirmed legacy replacement retires its exclusive original only after commit.

Cancel removes only the current UUID directory. Archive/discard uses the same cleanup. Validation and persistence failures keep fields and pending selections available for retry. Corrupt/unavailable staged originals produce a recoverable error; discard the editor and select the source again. If the original reference identity changed elsewhere, reopen the editor to review it. Filesystem and database operations are not represented as one atomic transaction: the promotion, rollback, commit witness and locked orphan recovery explicitly cover that boundary.

Stage3B adds Room24 ordered associations while these controls remain scalar. The manifest retains visual/audio selections and adds baselineVisual/baselineAudio identity-order arrays. Old manifests normalize to their reviewed singleton baseline; a later collection change fails closed until reviewed again. Save replaces/removes only the explicitly reviewed first source, preserving other links and their local work; null never means remove all. Atomic NIO manifest replacement keeps the prior draft if replacement fails. No temporary association schema or new file ownership system is introduced. Stage3C will version and expand staging into full collections, all-item recovery receipts and controls.
