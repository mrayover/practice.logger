## Future processing dependency — documentation only

composer_soundfont.cpp currently calls tsf_render_float for each bank into one shared interleaved stereo accumulation buffer, then clamps final PCM. Bank output can contain multiple track channels, so processing that sum cannot provide independent channel EQ or width. A minimal future design would isolate channel-tagged voices into bounded per-channel stereo scratch buffers, process each strip before summation, then retain the final limiter/output path. Any TSF render-filter extension must advance each voice exactly once per audio block; do not render the whole bank separately for every channel. Assess CPU/memory and preserve the single worker, bank/sample ownership and voice tokens before implementation.

Future channel processing can include separate channel pan, actual stereo width, four-band low shelf / low-mid peak / high-mid peak / high shelf EQ and effects slots. Channel pan is distinct from C4A preset sound-shaping pan. Persistent channel/master settings require a later explicit project-format decision. None are C4C controls or implementations. Arrange playback/exports/Composer portable recovery remain C5/C6/C7. Practice ZIP/JSON still exclude Composer projects and custom presets.
